# gogo (движок картирования и фингерпринта внутренней сети)

`gogo` = **высокопараллельный, малшумный и гибко настраиваемый движок картирования**. От Chain Reactors, спроектирован под red team во внутренней сети:
принцип минимального числа пакетов, активный и пассивный фингерпринт, извлечение ключевых данных, POC-движок уровня ядра (neutron, совместим с шаблонами nuclei),
поддержка собственных DSL/workflow. **Сначала gogo разворачивает поверхность, затем fscan бьёт по точкам.**

## Разделение с fscan

| | gogo | fscan |
| --- | --- | --- |
| Сильная сторона | Картирование больших сегментов, фингерпринт, извлечение данных, управляемые пакеты | Брутфорс слабых паролей, доступ без авторизации, критичные уязвимости, эксплуатация |
| Шум по умолчанию | Низкий (`--opsec`, потоки/таймауты настраиваются) | Высокий (600 потоков + брутфорс + POC целиком) |
| Вывод | `.dat` (deflate JSON Lines) + форматирование | txt/json/csv |
| Типичное использование | `gogo -i 10.0.0.0/8 -m ss --ping -p top2,win,db --af` | `fscan -h 10.0.0.0/24 -nobr -nopoc` |

Установочный скрипт gogo не скачивает — положите его по пути основного файла самостоятельно. Файлы для Windows и ARM тоже нужно добавить самому; на текущей платформе используется только основной файл выше.

**Без зависимостей**: один статический бинарник, фингерпринты и правила извлечения встроены, работает даже на Windows 2003. Дополнительные файлы конфигурации **не нужны**.

## Дисциплина

1. **Область**: через `--exclude` / `--exclude-file` исключайте сегменты вне авторизованной области, не сканируйте офисную сеть и сегменты метаданных облака.
2. **Сначала разведка маршрутов, потом сканирование**: `ip a; ip route; arp -a; cat /etc/hosts` — топология внутренней сети часто экономит половину сканирования.
3. **OPSEC**: в чувствительной среде добавляйте `--opsec`, потоки держите в `-t 200~500`, таймаут `-d 3`; для больших сегментов обязательно сначала фильтр `--ping`.
4. **Не сканируйте большие сегменты с `-p -` (все порты)** — это самоубийственный объём пакетов; сначала `top2`, потом все порты по живым хостам.

## Ключевые понятия

### Пресеты портов (душа этого инструмента)

```bash
gogo -P port        # вывести все предустановленные tag и соответствующие порты
```

Частые tag: `top1`(80,443,8080) · `top2`(сотни частых Web/сервисных портов) · `top3` · `common`(частые во внутренней сети) ·
`win`(135,137,445,3389,winrm,oxid) · `db` · `http` · `docker` · `oracle` · `smb` · `all`(всё)

```bash
комбинация: -p top2,win,db          # любое сочетание через запятую
диапазон: -p 1-1000               # интервал
все порты: -p -                    # эквивалент 1-65535 (осторожно)
отдельные порты: -p 6379,mysql,12345
```

### Три режима сканирования

| Режим | Параметр | Когда применять |
| --- | --- | --- |
| default | (по умолчанию) | один IP / небольшой сегмент (до /24) |
| smart | `-m s` | /24~/16, зондирование AB-сегментов + эвристическое расширение |
| supersmart | `-m ss` | большие внутренние сети от /16: сначала точки, затем отбор подсетей |
| sc | `-m sc` | сегмент цели известен, нужен более плотный охват портов |

```bash
gogo -i 192.168.1.0/24 -m s  --ping -p top2,win,db --af
gogo -i 10.0.0.0/8    -m ss --ping -p top2,win,db --af
```

### workflow (сохранить сложную команду как пресет)

```bash
gogo -P workflow     # вывести все workflow
gogo -w 10           # эквивалент полного supersmart-прохода по 10.0.0.0/8 (все порты)
gogo -w 172          # 172.16.0.0/12
gogo -w 192          # 192.168.0.0/16
gogo -w interc       # частые подсети C внутренней сети (три блока 10/172/192)
gogo -w 10 -i 11.0.0.0/8 -p top2   # параметры workflow можно переопределить в командной строке
```

## Краткий справочник параметров (проверено на v2.15.0 `-h`)

> **Для длинных многобуквенных параметров обязательны два дефиса**: `--ipp`, `--sp`, `--ef`, `--af`. Один дефис — только для односимвольных вроде `-i/-p/-m/-t/-d/-e/-v/-w/-F/-l/-L/-j`.

**Ввод**
```
-i/--ip   192.168.1.1/24,172.16.1.1/24   цели, несколько через запятую
--exclude 10.0.0.1/24        --exclude-file <file>
-l <file> файл со списком целей        -L  читать цели из stdin
-j <file> продолжить по прошлому результату (.dat) или списку ip:port, углубляясь дальше     -J  читать из stdin
```

**Вывод**
```
-f <file>        имя файла вывода         --path  каталог вывода
-o <fmt>         формат вывода в консоль     -O <fmt>  формат вывода в файл (по умолчанию jsonlines)
--af             автоименование файла вывода (.dat, deflate JSON Lines)
--hf             автоименование скрытого файла   -C  отключить сжатие      --tee  дублировать вывод в консоль
-q/--quiet       отключить логи, оставить только результат (обязательно при связке с другими инструментами)
-F <file>        отформатировать готовый .dat
--filter / --output-filter / --scan-filter   фильтрация истории / фильтрация в реальном времени / ранняя остановка
```

**Умное сканирование**
```
-m/--mod  default|s|ss|sc    режим сканирования
--ping                       сначала фильтр по ICMP (для больших сегментов обязательно)
-n/--no                      только умное сканирование, без перехода в обычное
--sp   проба портов в smart (по умолчанию 80, в режиме ss — icmp)
--ipp  проба IP в AB-сегменте (по умолчанию 1,254)
```

**Производительность и скрытность**
```
-t/--thread <n>     параллельность (в linux по умолчанию 4000, для внутренней сети рекомендуется 200~1000)
-d/--timeout <с>    таймаут (по умолчанию 2)
-D/--ssl-timeout     таймаут SSL
--opsec             режим низкого шума (включать в чувствительной среде)
-s/--spray          распыление по портам в приоритете (включается автоматически при >500 портов)
--no-spray          принудительно отключить распыление
```

**Фингерпринты и извлечение**
```
-v/--verbose         активный фингерпринт (без него только пассивный: меньше данных, но тише)
--ff <file>          собственный набор фингерпринтов
--extract "<regex>"  собственное регулярное выражение для извлечения
gogo -P extract      посмотреть встроенные правила извлечения (jwt / mail / idcard / phone / ip и др.)
```

**Уязвимости (ядро neutron)**
```
-e/--exploit         включить сканирование POC (вместе с -v пишется -ev)
-E <name>            имя конкретного шаблона        --ef <file>  файл шаблона
--payload <s>        указать payload      --attack-type sniper|clusterbomb|pitchfork
```

**Прокси**
```
--proxy socks5://127.0.0.1:11111      # проверено, работает через туннель suo5 / ssh -D
```

## Стандартный порядок работ (SOP)

```bash
# 0) разведка маршрутов
ip a; ip route; arp -a; cat /etc/hosts /etc/resolv.conf

# 1) картирование большого сегмента (тихо, сначала живость, результат в файл)
./gogo -i 10.0.0.0/16 -m ss --ping -p top2,win,db --af -t 500 -d 3

# 2) посмотреть результат (человекочитаемо)
./gogo -F ./.10.0.0.0_16_top2_win_db_ss_dat

# 3) по живым хостам все порты + активный фингерпринт
./gogo -i 10.0.1.0/24 -p - -v -t 1000 -d 3 --af

# 4) точечно прогнать POC (только по целям с подтверждённым фингерпринтом)
./gogo -i 10.0.1.5,10.0.1.9 -p top2 -ev -E <имя_шаблона>

# 5) продолжить по результату предыдущего шага (без повторного сканирования)
./gogo -j ./step1.dat -p 1-65535 -v -e
```

### Картирование через туннель (основной путь при работе во внутренней сети)

```bash
# предусловие: навык suo5-tunnel поднял socks5 либо ssh -D из vps-reverse-shell
./gogo -i 10.0.0.0/16 -m ss --ping -p top2,win,db --af \
       --proxy socks5://127.0.0.1:1080 -t 300 -d 5 -q

# проверено: gogo --proxy socks5:// действительно заводит трафик в туннель (через VPS виден SSH-фингерпринт самого VPS)
```

В сценарии с туннелем снизьте `-t` до 300 и поднимите `-d` до 5, иначе туннель начнёт терять пакеты и давать ложные вердикты.

## Запись результатов в базу (обязательно)

`.dat` у gogo — сжатый JSON Lines: сначала форматируйте, затем разбирайте и вносите в базу:

```bash
./gogo -F ./result.dat -o json -f result.json      # преобразовать в JSON (структура реального результата ниже)
python3 tools/parse.py result.json
# ключевые моменты разбора: верхний уровень {config, ip, data:[...]}, каждая запись содержит ip/port/protocol/status/frameworks/title/timing
```
```python
import json
d = json.load(open('result.json', encoding='utf-8'))
for it in d.get('data', []):
    fw = ','.join((it.get('frameworks') or {}).keys())
    print(it.get('ip'), it.get('port'), it.get('protocol'), fw, it.get('title'))
# пример одной реальной записи: {"ip":"10.0.0.5","port":"22","protocol":"tcp","status":"open",
#             "frameworks":{"ssh":{"name":"ssh","attributes":{"version":"10.3p1"}}},
#             "title":"SSH-2.0-OpenS","timing":26}
```

```bash
# дисциплина записи (как у fscan)
redteam_asset_add      { engagement, ip, port, service, title, source: "gogo", tags: [...] }
redteam_web_list       # далее URL и заголовки дополнит навык веб-фингерпринта
redteam_vuln_add       { engagement, target, name, severity, evidence_ref }   # обязательно с доказательством
```

**Внимание**: результаты по фреймворкам и фингерпринтам gogo записывайте в поле `fingerprint` у `asset`, не оставляйте только в терминале.
Извлечённые чувствительные данные (почта/удостоверение личности/JWT) относятся к зачётному пункту «массовые чувствительные данные» — фиксируйте их через `redteam_vuln_add` +
`redteam_score_hit`, доказательства — в `runs/`.

## Устранение проблем

| Симптом | Что делать |
| --- | --- |
| Ошибка параметров | для длинных параметров два дефиса (`--af`, а не `-af`), `-P` принимает только `port/workflow/neutron/extract` |
| Файл результата не найден | `--af` пишет **в каталог с бинарником**, добавьте `--path` для нужного каталога |
| По большому сегменту почти нет результатов | `--ping` пропускает хосты, блокирующие ping: уберите `--ping` или настройте пробу через `--ipp` |
| Сканирование слишком медленное | поднять `-t`, снизить `-d`; заменить `-p` на `top1`/`top2`; для больших сегментов `-m ss` |
| Замечен IDS | `--opsec` + `-t 200` + `-d 3`; не включать `-e`; не использовать `-p -` |
| Много таймаутов в туннеле | снизить `-t`, поднять `-d`: узкое место — пропускная способность туннеля |
| Нужны только результаты без логов | `-q` (обязательно при связке с другими инструментами) |

## Связанные навыки

- `fscan-intranet`: брутфорс и эксплуатация после картирования
- `suo5-tunnel`: WebShell → SOCKS5, даёт gogo вход с `--proxy`
- `vps-reverse-shell`: туннели и доставка payload
- `web-fingerprint` / `asset-correlation`: дальнейшая связка результатов gogo в граф активов
