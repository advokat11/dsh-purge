# nuclei (шаблонное обнаружение уязвимостей)

`nuclei` — **основная сила** этапа поиска уязвимостей: одна команда покрывает CVE, раскрытую поверхность, ошибки конфигурации, пароли по умолчанию, доступ без авторизации.
Библиотека шаблонов уже на месте (пути ниже), **не ищите POC в интернете заново**.

## Бинарник и шаблоны на этой машине

| Пункт | Значение |
| --- | --- |
| Бинарник | `/usr/bin/nuclei` (v3.11.1) |
| Библиотека шаблонов | `~/.local/nuclei-templates` (**13,742 шаблона**) |
| Версия шаблонов | v10.4.9 (обновлено 2026-09-18) |
| Конфигурация | `~/.config/nuclei/config.yaml`, `.templates-config.json` |

Распределение шаблонов (в отчёте ссылайтесь по категориям): `http/` 11,364 (из них `http/cves` 4,320, `http/misconfiguration` 981,
`http/vulnerabilities` 961, `http/exposures` 707, `http/default-logins` 307), `cloud/` 663, `file/` 447,
`network/` 282,`dast/` 251.

**Обновление шаблонов**: `nuclei -update-templates` (не чаще раза в неделю; после обновления сначала прогоните `-tl`, чтобы убедиться, что всё цело).

## Базовое использование

```bash
# 1) быстрая проверка одной цели (сначала видно, на что сработает, без реального удара)
nuclei -u https://target.example.com -severity critical,high,medium -rl 30 -c 15

# 2) массово: список живых URL, выгруженный из базы активов
nuclei -l runs/alive-urls.txt -severity critical,high -rl 50 -c 25 \
  -jsonl -o runs/nuclei-$(date +%m%d-%H%M).jsonl

# 3) конкретные шаблоны (известная версия компонента → точный удар: высокая результативность, мало шума)
nuclei -u http://target:8080 -t http/cves/2021/CVE-2021-44228.yaml
nuclei -u http://target -t http/exposures/ -t http/default-logins/

# 4) массово по тегам (tags)
nuclei -l runs/alive-urls.txt -tags seeyon,weaver,panel,exposure -rl 20

# 5) только перечислить шаблоны к запуску (пакеты не отправляются, сначала оценить покрытие)
nuclei -l runs/alive-urls.txt -tags cve -tl
```

## Ключевые параметры (частые в этом сценарии)

| Параметр | Действие | Рекомендация |
| --- | --- | --- |
| `-rl` | Лимит запросов в секунду | С интернета 30–50; если поймал WAF — снизить до 5 |
| `-c` | Число параллельных шаблонов | 15–25; выше — можно уронить небольшой сайт |
| `-severity` | Только указанные уровни | В учении важны `critical,high` (средние и низкие очков не дают) |
| `-tags` / `-t` | Отбор шаблонов | При зацепках по фингерпринту — в приоритете, не бейте всё подряд |
| `-jsonl -o` | Структурированный вывод | **Обязательно в `runs/`**, отчёт ссылается на него |
| `-proxy` | Через прокси | Для снижения шума — `cn-proxy-pool`; **цели во внутренней сети — через туннель suo5 с `-proxy socks5://127.0.0.1:1080`** |
| `-H` | Свой заголовок | С Cookie/Token проверять функции после входа |
| `-duc` | Отключить проверку обновлений шаблонов | Экономит время при массовых прогонах |
| `-stats -si 30` | Вывод прогресса | Для долгих задач видеть прогресс |

## Взаимодействие с базой знаний (сначала поиск, потом удар; дублирование запрещено)

Перед началом — `redteam_poc_search` (по CVE / компоненту / версии / признаку в теле): он сразу смотрит два уровня — **локальную базу знаний POC и локальную библиотеку шаблонов nuclei**.
При попадании берите полный текст через `redteam_poc_get` либо сразу `nuclei -t <шаблон>`; только если нет ни там, ни там — ищите в интернете, и лишь в конце пишите руками.

Проверенные рабочие новые шаблоны/EXP возвращайте в базу знаний через `redteam_poc_add` (с `category` + `engagement` + `asset_target` + `verified` + `verified_note`, маскируя данные текущей цели).

## Снижение шума и самосохранение (важно)

1. **В ignore по умолчанию уже исключены опасные теги**: в `~/.config/nuclei/.nuclei-ignore` по умолчанию игнорируются `dos`, `local`, `fuzz`, `bruteforce`, `txt-service` —
   **не убирайте эти исключения, чтобы «бить полнее»**: шаблоны класса DoS положат продакшн-систему и просто уничтожат учение.
2. **Сначала зондирование, потом огонь**: начните с прогона `-severity critical,high`; после попаданий углубляйтесь по конкретным находкам, не начинайте с полного объёма.
3. **WAF и блокировки**: при блокировке снизьте `-rl` до 5 и добавьте `--delay 1s`, смените UA (`-H "User-Agent: ..."`),
   при необходимости меняйте выход через навык `cn-proxy-pool`; **больше 3 блокировок по одной цели — сразу прекращать** (`redteam_asset_test` status=abandoned + blocked=true) и переходить к следующей цели.
4. **На продакшн-системах избегайте пиковых часов бизнеса**: шаблоны с заданиями по расписанию и массовыми задачами (например запускающие синхронизацию или перестройку индексов) сначала проверяйте на тестовых/предпродукционных активах.

## Вывод и запись в базу (обязательно)

Сразу после прогона пишите в базу, **не откладывайте на конец**:

1. Читайте `runs/nuclei-*.jsonl` и по одной записи вызывайте `redteam_vuln_add`:
   - `title` (имя шаблона + точка попадания), `severity`, `cve` (`classification.cve-id` из шаблона), `target` (**с портом**),
     `evidence` (выдержка ответа/признаки ответа/matched-at), `confidence=confirmed` (попадание nuclei — уже подтверждённое наличие на уровне ответа),
     `gained` (что через это можно получить), `agent=vuln-scan`.
2. **К каждой подтверждённой уязвимости — запись `redteam_http_evidence_add`**: строка запроса + Host + ключевые заголовки запроса + выдержка ответа (поле `curl-command` шаблона подходит напрямую).
3. Каждое ключевое действие — `redteam_chain_add`: `stage_code=recon` или `internet`,
   в `tool` — **фактический текст команды** (например `nuclei -l runs/alive-urls.txt -severity critical,high -rl 50 -jsonl -o runs/nuclei-0918.jsonl`),
   в `result` — выдержку вывода (например `попаданий 3: CVE-2023-xxxx (critical)…`).
4. Сразу после проверки актива пишите обратно через `redteam_asset_test`: `status` (testing/tested/no_surface/blocked), `test` (вывод в режиме добавления), `surface` (что ещё можно проверить).
5. **Фиксируйте только то, что даёт очки**: утечки информации, раскрытие версий, CORS/CSRF, SSL и заголовки ответа, не влияющие на зачёт, — **не более одной строки-исключения**, не углубляйтесь и не повторяйте прогоны.

## Частые проблемы

| Симптом | Причина | Что делать |
| --- | --- | --- |
| Ни одного попадания | цель не HTTP или шаблоны в ignore | добавьте `-tl` и посмотрите, какие шаблоны реально запускались; проверьте протокол `-t http/` против `network/` |
| Много `could not resolve` | в списке URL есть мёртвые ссылки | сначала отфильтруйте живые через `pd-httpx`: `pd-httpx -l all.txt -o alive-urls.txt -silent` |
| Много low/info | severity не ограничен | в учении добавляйте `-severity critical,high,medium` |
| Цель упала | слишком высокая параллельность / запущены шаблоны dos | снизить `-rl`/`-c`; убедиться, что ignore-файл не менялся |
| Цель во внутренней сети недостижима | нет туннеля | добавить `-proxy socks5://127.0.0.1:<порт_suo5>` (навык `suo5-tunnel`) |
